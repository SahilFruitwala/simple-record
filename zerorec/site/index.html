TRANSPARENCY & METHODOLOGY

The "Sleeping Parent" Investigation

How a rigorous benchmark harness uncovered two subtle measurement traps in naive screen recording comparisons.

The Naive Trap

Why Naive Numbers Were Flawed

  • The "Sleeping Parent" Bug: ZeroRec uses macOS posix_spawnattr_setdisclaim for TCC permission isolation. The parent process spawns a disclaimed worker process and sleeps in waitpid(). The original python script only monitored the parent PID, reporting an artificial 0.1% CPU!
  • The Unthrottled FFmpeg Bug: The FFmpeg command lacked the -re (real-time) input flag. FFmpeg processed frames as fast as possible (~190 fps), encoding all 600 frames in 3.1 seconds and artificially pegging CPU to 224%.
  • The Result: An unmeasured sleeping parent was compared against an unthrottled batch job.
The Rigorous Fix

Scientifically Fair Benchmarking

  • Process-Tree Aggregation: Added REC_NO_DISCLAIM=1 so ZeroRec runs directly in the monitored process without re-execing, and added pgrep -P to aggregate the entire process tree.
  • 1.0× Real-Time Cadence: Added -re to FFmpeg so both engines encode at a strict 60.0 fps real-time pacing across the full 10.0 seconds.
  • The Bottom Line: ZeroRec is still 13.1× more CPU-efficient than FFmpeg (16.4% vs 215.0% at 4K60), with 100% reproducible and verifiable numbers.
